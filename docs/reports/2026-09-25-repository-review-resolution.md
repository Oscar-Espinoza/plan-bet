## Deploy notes

- **Run `pnpm db:migrate` before deploying.** Migration `0015_mushy_thor` adds a nullable `wagers.idempotency_key` column and a unique index on `(user_id, idempotency_key)`. `/api/health` reports `outdated` until the migration is applied.
- A slip that loaded before the deploy sends no idempotency key. It still works, but without replay protection.
- The lock scheme is safe during a rolling deploy. Classid 4 stays the placement lock, so old and new placement code still exclude each other. A reset on old code, which takes classid 3, could still race a placement on new code for as long as both versions are serving.

## Behaviour changes

- Live games no longer carry `result`, so the scorebug and slate show no score for them.
- A game with status `unknown` used to void through the missing-result path. It now stays open until reconciliation gives it a terminal status.
- Without a working quota store, the buddy never calls OpenAI. That includes local dev with `OPENAI_API_KEY` set and no `DATABASE_URL`. It gives the deterministic reply instead.
- When a transport error hides whether a bet was placed, the slip now says "We couldn't confirm the bet. Try again — it won't be placed twice." A new Spanish string was added.
- The settle cron now makes up to one extra provider request per sport, and only when there are open wagers on games that are past kickoff and not terminal.

## Open items

- **Unverified against the live API:** Agent A assumed football-data v4 honours `ids` on `/matches` without its default today-only date window. If it doesn't, soccer reconciliation of older fixtures silently returns nothing; that is harmless, but it fixes nothing. Check with one call. The fallback is per-id `/matches/{id}`.
- **Settlement doesn't take the balance lock.** It only credits, so it can't make a balance negative. A return that commits during a reset can leave the account at 1,000 plus that return instead of exactly 1,000. This is accepted.
- **Kept enrichment facts aren't labelled stale.** They carry their older `observedAt`, but `EvidenceFact` has no per-fact stale flag. Adding one would mean a contract change.
- **Optional indexes** if volume grows: an expression index on `games ((summary->>'status'))` and one on `wagers (scheduled_at, id)`.
- **No automated tests** (per `AGENTS.md`). The concurrency fixes (#2, #7, #8) were checked by reading the SQL. The ordering fixes (#1, #3, #9, #10) were checked with in-memory probes.
