- Relative imports inside `src/lib/server/**` and `src/lib/shared/**` (the jobs Worker bundles them with wrangler/esbuild, not Vite).

## Pieces

1. **Providers** → `src/lib/server/providers/`: port `legacy/src/providers/**`: `football-data`, `mlb-stats`, `baseball-savant`, `api-sports`, `apifootball`, `bigballs`, `openai/client.ts` (copy only; T12 wires it), `mcp-http.ts`, `provider-error.ts`, `registry.ts` and `contracts.ts`. Keep timeouts, bounded body sizes and `ProviderError`. If `csv-parse` is used, add it as a dependency and confirm it bundles for Workers.
2. **Refresh** in `src/lib/server/data/sports-data.ts`: port the write side of legacy `sports-data.ts`:
   - `refreshSportData`, `refreshSoccerData` and `refreshBaseballData`, the in-process single flight, `cachedMetadata`, ingestion logging and the lease.
   - Use the T02 repository: `persistSportsTeamData` (one batch per team), `acquireRefreshLease` and `completeRefreshLease`.
   - Replace `after()`/`revalidateTag` with a call to `publishReadModels()` (piece 4) after each successful team persist.
   - A failed refresh never overwrites last-known-good.
3. **Enrichment:** port `legacy/src/data/fixture-context.ts`, `fixture-facts.ts` and `fixture-context-repository.ts` (D1 version) to `src/lib/server/data/`. `mergeFacts` keeps its per-source rule: a failed source keeps its stored facts with their original `observedAt`, and `undefined` is never collapsed into `[]`.
4. **KV read models** in `src/lib/server/data/publish.ts`:
   - `board:v1`: the `BoardData` object `legacy/src/app/page.tsx` builds (team, games, freshness inputs per slug, without team `context`), stored with each stored expiry so freshness is still derived at read time.
   - `game:v1:<routeId>`: the stored game detail the game page needs (snapshot, fixture context facts, expiry), keyed by the team-perspective **route id**. That is how pages look games up; this overrides the `canonicalGameId` key in spec §3.5.
   - `routes:v1`: route id → canonical game id.
   - `publish:version`: read it, add 1, write it back, after the other keys.
   - Writes happen only after a successful D1 persist. A KV write failure is logged at `warn` and never throws into the refresh.
5. **Restore the fixture-context merge** that T02 deferred: in `getGameDetail`, after the stored snapshot is read, merge `readFixtureContext(routeId)` with `withContextFacts`, exactly as `legacy/src/data/sports-data.ts` does (a missing or invalid row leaves the snapshot unchanged). The KV `game:v1:<routeId>` value already holds the merged facts.
6. **Read path:** in `sports-data.ts`, `getCachedDashboardData()` and `getGameDetail()` read KV first. Memoize per isolate for 10 s. Then D1 (T02 functions), then the demo seed, with freshness derived at read time from the stored expiry. `scheduleRefresh(sport)` becomes `waitUntil(env.JOBS.refresh(sport))`, guarded with try/catch and skipped when `JOBS` isn't bound. The request path never calls a provider directly.
7. **Jobs Worker** `workers/jobs/`:
   - `wrangler.jsonc` per spec Appendix H, with preview D1 `matchday-preview` (`d5c258c4-491c-465e-834b-ab2aa0216924`) and KV `8a316593b062493cacddfe7b89d63f2f`.
   - `src/index.ts` exports a default `{ scheduled }` handler mapping the three cron expressions to refresh (both sports, `Promise.allSettled`), settle and enrich.
   - It also exports `class Jobs extends WorkerEntrypoint` with `refresh(sport)`, `settle()`, `enrich()` and `publish()`. Each returns the same summary shape the legacy cron routes return. `settle()` returns `{ skipped: "settlement arrives in T09" }` for now.
   - Add `pnpm` scripts `jobs:deploy:preview` and `jobs:dev`.
8. **App wiring:**
   - Add the `services` binding `JOBS` → `matchday-jobs-preview` with entrypoint `Jobs` to the app's preview env in `wrangler.jsonc`. Add `JOBS` to the `cloudflare:workers` env type.
   - Port `/api/cron/refresh`, `/api/cron/settle` and `/api/cron/enrich` as `+server.ts` with GET and POST. Same bearer check (`cron-auth.ts`), same 503 when `CRON_SECRET` is missing, always 200 with the summary when authorized. They forward to `env.JOBS`.
9. **Preview setup** (allowed by the guard):
   - Apply the T02 migrations to the remote preview database: `pnpm wrangler d1 migrations apply DB --remote --env preview`.
   - Deploy the jobs Worker, then the app (`--env preview`).
   - Generate a random `CRON_SECRET` and set it on both preview Workers with `wrangler secret put CRON_SECRET --env preview`. Write it to `.dev.vars` in your worktree as `CRON_SECRET=...`, and add `.dev.vars` to `.gitignore` first. Never commit or print secrets in the log.
   - Football and api-sports tokens are set by the coordinator; baseball (MLB Stats, Savant) needs no token.
