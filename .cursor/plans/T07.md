## Facts you need

- The auth tables (`user`, `session`, `account`, `verification`) already exist from T02 with Better Auth's core columns. The starting grant is a **database trigger** (`user_starting_grant`, reason `signup`, 1000 credits). **Never insert a grant from application code.**
- No `platform`: `import { env } from "cloudflare:workers"`. String secrets are also on `process.env` (nodejs_compat).
- `hooks.server.ts` and `src/lib/server/edge-cache.ts` exist from T04. `locals.signedIn` is "a session cookie is present"; you add `locals.user`. The edge cache must keep bypassing whenever a session cookie is present. Don't weaken that.
- Better Auth 1.7.x; SvelteKit 3 imports (`$app/env` has `building`).

## Pieces

1. **`src/lib/server/auth.ts`:**
   - Better Auth with `drizzleAdapter(getDatabase(), { provider: "sqlite", schema })`.
   - `secret` from `BETTER_AUTH_SECRET`; `baseURL` from `PUBLIC_SITE_URL`.
   - `session.cookieCache: { enabled: true, maxAge: 300, strategy: "compact" }`.
   - Social providers built from env exactly as legacy `configuredProviderNames()` decides: GitHub when `AUTH_GITHUB_ID` and `AUTH_GITHUB_SECRET` are set, Google when `AUTH_GOOGLE_ID` and `AUTH_GOOGLE_SECRET` are set.
   - Account linking equivalent to legacy `allowDangerousEmailAccountLinking: true` on both: `account.accountLinking: { enabled: true, trustedProviders: ["google", "github"] }`.
   - Port `isTrustedProviderEmail`: a Google sign-in whose profile has `email_verified !== true` is refused, with the same user-facing outcome as legacy (back to `/sign-in` with an error). Use the Better Auth hook that runs before account/user creation for social sign-in; cite the doc you used in the log.
   - Better Auth requires a non-null `name`; if a provider gives none, use the email's local part.
   - Export `isAuthConfigured()` (`BETTER_AUTH_SECRET` + at least one provider + the `DB` binding), `configuredProviderNames()`, and `requireAccount()` with the legacy return shape (`{ ok: true, userId, email, name, image } | { ok: false, reason: "unconfigured" | "unauthenticated" }`). `requireAccount()` reads `locals.user` (pass the event, or use `getRequestEvent()` from `$app/server` if SvelteKit 3 has it; check the docs). It must not call Better Auth at all when unconfigured.
2. **`hooks.server.ts`:** mount the Better Auth handler at `/api/auth/*` via `svelteKitHandler` (only when configured), and fill `locals.user` and `locals.session` from `auth.api.getSession({ headers })` (cookie cache first). Keep T04's order: the edge-cache decision still uses `locals.signedIn`, decided before rendering, and auth routes are never cached.
3. **Maintenance switch** (spec §3.8): when `MATCHDAY_MAINTENANCE === "1"`, any non-GET request under `/api/` (including `/api/auth/*` sign-in) returns 503 with the legacy error envelope and code `maintenance` (`apiFailure` from `src/lib/server/api-response.ts`). The shell shows the existing `ui/banner` with a maintenance message in English and Spanish (add the Spanish string to `messages.es.json`).
4. **Request guards:** confirm `isSameOrigin` and `readJsonBody` from `src/lib/server/api-request.ts` work with SvelteKit's `Request`, and document the reference order (`isSameOrigin` → `requireAccount` → `readJsonBody`) in a comment where mutation routes will import them.
5. **`/sign-in`:** port `legacy/src/app/sign-in/page.tsx`: provider buttons for the configured providers only, the same copy and layout, and the error states. Sign-in posts through the Better Auth client to `/api/auth/sign-in/social` with a callback back to the page the user came from. Load `better-auth/client` (or `better-auth/svelte`) only on this page, and only the parts it needs. Check the `/` budget is unchanged.
6. **Account control** in the app shell: port `legacy/src/components/account-control.tsx`.
   - Unconfigured: nothing.
   - Signed out: a "Sign in" button.
   - Signed in: the balance chip and open-wager count, from **one** `db.batch()` that reads `SUM(credit_entries.amount)` and the open-wager count. Port `getCreditSummary`'s balance part and `countOpenWagers` minimally, in `src/lib/server/data/credits.ts` and `wagers-repository.ts`; T08 extends them. Money renders in chalk + DM Mono, never the accent.
   - The data comes from `+layout.server.ts`. A signed-in render is `private, no-cache` (T04).
7. **Sign-out:** a POST form or action that calls Better Auth sign-out and redirects to `/`, ready for the `/you` settings row (T08 places it).
8. **Preview:** set a random `BETTER_AUTH_SECRET` on the preview app with `wrangler secret put --env preview` and note in the log that you did. Don't set OAuth client secrets: the coordinator sets them, and sign-in on the preview is tested after that.
