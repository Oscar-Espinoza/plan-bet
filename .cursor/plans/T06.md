## Facts you need

- Reuse what exists: the shell, CSS (including `matchup.css`, already loaded with the shell), `navigation-preview`, `fast-link`, `local-date-time`, `team-logo`, `stadium-preload`, `ui/*` and `section-tabs` (if T05 ported it). ## Pieces

1. **`src/routes/games/[id]/+page.server.ts`:** port `legacy/src/app/games/[id]/page.tsx`'s public parts.
   - `getGameDetail(params.id)`, then 404 with `error(404)` when missing, or when `getTeam(snapshot.game.teamSlug)` is missing. An unknown id must never call a provider.
   - Return `view: buildMatchView(snapshot, team)` plus the few raw fields the skeleton needs (sport, finished, home, away).
   - Metadata (`generateMetadata`): title and description through `<svelte:head>`, translated, same strings as legacy.
2. **Components** (`src/lib/components/` and `src/lib/components/matchup/`), keeping DOM and class names: `game-detail`, `matchup/match-chrome` (tabs, breadcrumb), `matchup/scorebug`, `matchup/status-ribbon`, `matchup/context-blocks` and `matchup/bet-slip-skeleton`. Port `section-tabs` too if T05 didn't.
3. **`+page.svelte`:** `StadiumPreload` plus `GameDetail` with the wagering panel slot. The panel contains the signed-out wagering state from legacy `WageringPanel` and `BetSlip`, without any API calls; if legacy renders nothing for signed-out visitors, render nothing. The social slot is empty.
4. **Loading and preview:** the legacy `games/[id]/loading.tsx` is the destination preview. When `navigating.to` targets `/games/<id>`, show the match preview with the public fields the board row passed through `navigation-preview`, and the skeleton for a direct link. The geometry of the header and tabs must not jump when real content replaces the preview: within 1 px at 320, 390 and 1280, in both languages.
5. **Error:** port `legacy/src/app/games/[id]/error.tsx` into the route's `+error.svelte` if its copy differs from the root error page.
