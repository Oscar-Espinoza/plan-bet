# T13 plan: Speed pass and parity sweep

Builder: Composer 2.5. Branch: `cf/T13-speed` (checked out in your worktree). Tier C.
Read first: `docs/cloudflare-migration-spec.md` §1 (budgets), §3.4, §3.10, §5 (T13); `legacy/PERFORMANCE.md`; `docs/workflow.md` ("Keeping it fast"); `DESIGN.md`; the `Coordinator notes` and every ticket entry in `docs/migration-log.md` (the budget lines show how `/` grew: 30.8 KB → 54.5 → 65.1 → 67.8 → 69.0 KB gzip).

## Goal

Bring `/` back to the ≤ 60 KB gzip target, or as close as you can without removing behaviour. Add the remaining speed features. Then run one parity sweep of every route against production.

## Pieces

1. **Find where `/` JS comes from.** Using the client build manifest, list each chunk in the `/` first load with its gzip size and the modules inside it. `vite build --mode production` with `build.rollupOptions.output.manualChunks` off and a `rollup-plugin-visualizer`-style listing is fine; don't commit the visualizer. Report the top 10 contributors in the log.
2. **Cut it.** Typical wins to check, measuring each one:
   - Code that only signed-in or interactive features need, loaded on `/` for everyone: the account chip state, the buddy, dialogs and the Better Auth client. Move it behind dynamic `import()` or into the routes that use it.
   - Icon imports that pull whole sets.
   - The Spanish dictionary or locale code reaching English readers.
   - Navigation-preview and match-chrome code on the board's first load (load it on hover/intent instead, if legacy did).
   - Duplicate helpers bundled twice.
   Behaviour, DOM and visuals don't change. List each change with its byte saving.
3. **Service worker** (`src/service-worker.ts`): immutable build assets and fonts are cache-first. HTML and SvelteKit data requests are network-first, with the last good `/` as the offline fallback. **Nothing is cached when a Better Auth session cookie is present.** Version it with the SvelteKit build version so an update replaces old caches.
4. **View transitions:** `onNavigate` with `document.startViewTransition` where supported, cross-fade only, skipped under `prefers-reduced-motion`. No layout change.
5. **Early Hints:** add a `Link` header on HTML responses for the three preloaded fonts and the stadium image (`rel=preload`, correct `as` and `crossorigin`). Cloudflare turns these into 103 responses on a custom domain.
6. **Images:** add AVIF next to the WebP crests and stadium image (a `scripts/encode-images.mjs` using `sharp`, run once, outputs committed), served with `<picture>`. Row crests stay lazy; the stadium image keeps `fetchpriority="high"`.
7. **CSS inline experiment:** try SvelteKit's inline-style threshold so the global CSS is inlined. Keep it only if Lighthouse mobile LCP on `/` improves; record both numbers.
8. **OG image and icon:** `scripts/build-og.mjs` renders the legacy `opengraph-image.tsx` and `icon.tsx` designs to `static/og.png` (1200×630) and `static/icon.png`, using satori and resvg or a headless-Chrome screenshot, run once with outputs committed. Wire them into the layout's meta tags.
9. **Parity sweep:** a headless-Chrome script (not committed) visits every route on the preview and on production at 320, 390 and 1280 px in en and es: `/`, `/?sport=soccer`, `/?sport=baseball`, `/rules`, `/system`, two game pages (an upcoming baseball one and the soccer demo fixture), `/sign-in` and `/you` signed out. Record the largest box difference per route and width, console errors and HTTP status. Fix differences that come from the port. Differences from preview data (demo soccer, no finished games) are listed, not fixed.

## Acceptance (coordinator re-runs; paste commands and outputs in the log)

1. `pnpm check` prints `CHECK OK <sha>`. Report the `/` and `/games/[id]` budget lines: `/` ≤ 61,440 bytes is the target, and if it's still over, the log explains what remains and why.
2. Lighthouse 12 mobile (`npx lighthouse` with the mobile preset, median of 3) on the preview for `/` and one game page: performance score, LCP, CLS and total JS. Compare against `legacy/PERFORMANCE.md` (92/96, LCP 3.39/2.85 s, CLS 0.000).
3. With the service worker active, a second load of `/` with the network offline renders the last board. With a session cookie, the Cache Storage has no HTML entry (show the cache keys).
4. `curl -sI` of `/` on the preview shows the `Link` preload header.
5. The parity table from piece 9 is in the log.
