## Facts you need

- The shell, fonts, CSS, `fast-link`, `navigation-preview`, `language-provider`, `local-date-time`, `tour-bar`, `ui/*` and the edge cache exist from T04. Reuse them; don't recreate them.
- Data comes from `getCachedDashboardData()` in `src/lib/server/data/sports-data.ts` (T02 and T03). Call it from `+page.server.ts`. Never call a provider.
- Svelte 5 runes, SvelteKit 3, `@lucide/svelte` icons, no zod in client code.
- No `platform`: bindings come from `cloudflare:workers` if you need them (you shouldn't here).

## Pieces

1. **`src/routes/+page.server.ts`:** port `legacy/src/app/page.tsx`.
   - Resolve the sport from `?sport=` or the `sport` cookie, through `parseSportPreference` and `sportPreferenceSchema`.
   - Load the dashboard and return only `{ team, games, freshness }` per slug (the `BoardData` shape; no team `context`).
   - Keep `/` eligible for the edge cache: don't set cookies here.
2. **`src/routes/+page.svelte`:** `StadiumPreload` (port `stadium-preload.tsx`: a `<link rel="preload">` for the 800 px stadium image with `fetchpriority="high"`) plus `Slate`.
3. **`src/lib/components/slate.svelte`:** port `legacy/src/components/slate.tsx` and its helpers, keeping DOM structure and class names:
   - Fixtures grouped by day.
   - One-line rows: game, kickoff, chevron, both names ellipsized.
   - Status tags and the demo stamp.
   - Sport chips that switch locally: update the URL with `replaceState` from `$app/navigation` without a network request, and write the `sport` cookie with `sportPreferenceCookie`.
   - The empty and "Not provided" states.
   - Team crests via `team-logo.svelte` (port `team-logo.tsx`). Row crests use `loading="lazy"`; only hero crests are eager.
4. **Preloading** (legacy `fast-link` behaviour, using SvelteKit attributes):
   - The first four visible match rows: `data-sveltekit-preload-code="viewport"` and `data-sveltekit-preload-data="hover"`.
   - Other rows: `"tap"`.
   - On `navigator.connection.saveData` or a 2g/3g `effectiveType`: preload on tap only.
   - Match rows hand their public preview fields to `navigation-preview` as legacy `MatchLink` does.
5. **`src/routes/rules/+page.svelte`** (and `+page.server.ts` if it needs the translator): port `legacy/src/app/rules/page.tsx`, including the breadcrumb, `RULES_VERSION` and the translated copy. Page title through `<svelte:head>`.
6. If `section-tabs.tsx` is used by the board or rules, port it to `src/lib/components/section-tabs.svelte`. Otherwise leave it for T06.
